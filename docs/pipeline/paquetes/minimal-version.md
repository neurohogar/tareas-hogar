# Package: minimal-version

Epic E4 of `docs/v3/plan.md` («Versión mínima»): an optional field per task with a small version of the task («solo el inodoro»). In `pending` and `overdue` rows «Mínima: …» is shown with a «Hice la mínima» button, which completes the task like the checkbox; the completion remembers that it was the minimal one, and the undo notice and the Historial name it with the word «Mínima». The other field of the epic, «cuenta como hecha cuando…», is left out: it is a future feature of E4 (D13).

## Specs

Some passages below changed or no longer exist in `docs/spec.md` as they were quoted originally (mentions of effort, filters, **Solo rápidas** and Anotaciones were removed); the quotes follow the current translated spec where the passage still exists.

- **S1** (§4.1): «| `versionMinima` | string | no | One line with the small version of the task (see **Minimal version**, below). Any kind of task. |»
- **S2** (§4.1): «**Minimal version**: a single line, with no line breaks and no maximum length, for any kind of task («Solo el inodoro»). On save, spaces at the start and at the end are trimmed. Empty or only spaces means **no minimal version** (the field is not saved). A minimal version is never invalid: it never rejects the creation or the edit. A task saved without the field has no minimal version (there is no migration).»
- **S3** (§4.1): «The minimal version does not change the status (§5) or the order of the list, and the task name (below) is still emoji and title. The app does not suggest it or count it: it is offered the same way whenever it applies (§6.1), regardless of how overdue the task is or how many times it was done. The **Historial** and the undo notice only show the word «Mínima», never its text. Editing or emptying the minimal version does not touch the completions that were already the minimal one.»
- **S4** (§4.1): «Completing the task, by the checkbox, by «Hecho» or by «Hice la mínima» (on any step, §6.1), returns `pasoActual` to step 1, so a recurring task that comes back starts from the beginning. The completion stores in `pasoAlCompletar` the number of the step the task was on, also when it was completed with «Hice la mínima».»
- **S5** (§4.1): «for one completed with «Hice la mínima», it returns to the step it was on.»
- **S6** (§4.1): «(the word «Mínima» of the **Historial** and of the notice, §6.3 and §5.4, does not show steps)»
- **S7** (§4.4): «| `fueMinima` | boolean | no | `true` if the completion was «Hice la mínima» (**Minimal version**, §4.1). Without the field, the completion was the whole task (there is no migration). It is set on completion. |»
- **S8** (§4.4): «That a completion was the minimal one (`fueMinima`) is set on completion and not changed afterwards: a whole completion cannot be turned into a minimal one or the other way around; it is corrected by undoing and completing again. A completion of the minimal version counts like any other for the status and list rules (§5, §6.1, §6.2).»
- **S9** (§5.4): «If the completion was the minimal one (`fueMinima`, §4.4), the text adds « · mínima»: `Completaste «🌱 Regar» · mínima`; the rest of the notice does not change.»
- **S10** (§5.4): «A completion of the minimal version is deleted like any other (notice, **Historial** or the checkbox of the completed task) and the status is recomputed with those that remain. The checkbox of a completed task deletes the most recent completion, whether whole or minimal; that of a recurring task completed on an earlier day completes it again, as a whole.»
- **S11** (§5.5): «the checkbox that would complete is disabled (§6.1), and so is «Hice la mínima» (§6.1).»
- **S12** (§6.1): «If the task is `pending` or `overdue` and has a minimal version (§4.1), on its own line below the title (below the step line, if there is one), «Mínima: » followed by the text (for example «Mínima: Solo el inodoro»), and next to it the **Hice la mínima** button.»
- **S13** (§6.1): «The line is shown in full, on several lines if needed, without cutting, in the same size and secondary text color as the step line, without emphasis or its own color, and it is shown even if the task has no first step.»
- **S14** (§6.1): «**Hice la mínima** is a small text button, without its own color, like **Hecho** and **Paso anterior**; it completes the task like the checkbox (§5.4: it adds the completion with `fueMinima`, §4.4, and opens the notice «Completaste «…» · mínima» with **Deshacer**, and with «Vuelve …» below if it is recurring), on any step: in a task of two steps or more it stores `pasoAlCompletar` and `pasoActual` returns to step 1 (§4.1, **Steps**). It is disabled if the checkbox that would complete is (§5.5). Tapping it does not open the panel or go through **Unsaved changes**; tapping the text of the line outside the button is tapping the row (it opens the panel).»
- **S15** (§6.1): «It is not shown in `waiting` rows (nor the postponed or completed ones) or in the paused ones; it is decided with the status of each moment, and an `overdue` task with the checkbox disabled until its window opens (§5.5) shows it, with the button disabled. A postponed task can still be completed whole with the checkbox (§5.9), not with the minimal version. No texts that propose it, no counters or marks.»
- **S16** (§6.1): «**Hice la mínima** is not one of them: it does open the undo notice (below).»
- **S17** (§6.2): «- **Minimal version**: a one-line field with the label «Versión mínima», without example text, below the steps (after **Agregar paso**) and before the note. Enter in that field saves, as in every one-line field (**On-screen keyboard**, below). On create it starts empty; on edit, with the current value. Empty leaves the task without a minimal version (§4.1, **Minimal version**). It counts for **Unsaved changes** like any field: typing and going back to the original value does not count, nor do the spaces that **Guardar** trims; emptying an existing minimal version does.»
- **S18** (§6.2): «the first step and the more steps; the minimal version; the note»
- **S19** (§6.3): «If the completion was the minimal one (`fueMinima`, §4.4), the word «Mínima» after the time ("08:05 Mínima"), in the same secondary text, without color or icon; it never shows the text of the minimal version (the completion does not store it either).»
- **S20** (§6.3): «(and the word «Mínima» if it was the minimal one)»
- **S21** (§7): «(`emoji`, `nota`, `primerPaso` and `versionMinima` are independent fields, like `titulo`;»
- **S22** (§7): «The `fueMinima` data travels inside the completion: two devices that complete offline, one whole and the other with «Hice la mínima», leave both entries, each with its own.»

## Decisions

- D1 (2026-11-15, analyst, model of the field): the task gets an optional text field with the minimal version, for any kind of task (one-off and recurring, in any mode) and any effort. It follows the text rule of the first step (§4.1): a single line, with no line breaks and no maximum length; on save, spaces at the start and at the end are trimmed; empty or only spaces means **no minimal version** (the field is not saved); it is never invalid and never rejects the creation or the edit. Because it is the rule of the optional one-line texts of the task (first step, steps, annotation text) and rule 4 of the plan asks that everything new be optional and without obstacles.
- D2 (2026-11-15, analyst, existing tasks): there is no migration. A task saved without the field has no minimal version and its row and its panel look as they do today. Because "without the field" already means "without a value" in the optional fields of §4.1 (D9 of `first-step`).
- D3 (2026-11-15, analyst, where it is edited): in the panel (§6.2), **Tarea** section, a one-line field with the label «Versión mínima», without example text, below the steps (after **Agregar paso**) and before the note. Enter in that field saves, as in every one-line field (On-screen keyboard, §6.2). On create it starts empty; on edit, with the current value. Because the configuration goes in the panel (rule 6 of the plan) and the minimal version describes what to do, like the first step and the steps; an example text would be the app suggesting it (E4, "Avoid").
- D4 (2026-11-15, analyst, Unsaved changes): the field counts for **Unsaved changes** with the single definition of §6.2: typing and going back to the original value does not count, nor do the spaces that **Guardar** trims; emptying an existing minimal version does. Because it is the single definition of "there are changes" (D4 of `first-step`).
- D5 (2026-11-15, analyst, sync): it is an independent field of §4.1: the last change wins, per field, like `nota` and `primerPaso` (§7); an edit writes only if it changed. The data that marks a completion as the minimal one travels inside the completion, which is an independent document and is never lost (§7); two devices that complete offline, one whole and the other the minimal one, leave both entries. Because it is the conflict rule of the text fields of the task and of the completions.
- D6 (2026-11-15, analyst, counts as done): a completion of the minimal version is a completion like any other for all the status and list rules: the one-off task becomes completed (§5.1); in the relative one it restarts the interval (§5.2); in the calendar one and in those with several windows it covers the corresponding occurrence with the same rule (§5.3, §5.6, §5.7); it counts for "Mostrar completadas", the order (§6.1), **Última vez** (§6.2) and the checkbox of a completed task (§6.1), and a pause or a postponement behave the same. The minimal version does not change the status, the order, the filters or **Solo rápidas**. Because the plan says "Completing it counts as done", and a different status rule for the minimal version would make it a second-class completion (E4, "Avoid").
- D7 (2026-11-15, analyst, schedule): doing the minimal version is only possible inside the window, like completing (§5.5): if the checkbox is disabled by the window, the «Hice la mínima» button (D14, D18) is too. Undoing a completion of the minimal version is possible at any hour. Because D6 makes it a completion and §5.5 governs every completing (like the «Hecho» of the last step, D16 of `one-step-at-a-time`).
- D8 (2026-11-15, analyst, undo): a completion of the minimal version is deleted like any other, from the notice, the Historial or the checkbox of the completed task (§5.4, §6.1), and the status is recomputed with those that remain. The checkbox of a completed task deletes the most recent completion whether whole or minimal, and that of a recurring task completed on an earlier day completes it again, as a whole. Because completions are only added or deleted (§4.4) and the checkbox does not change meaning because of the minimal version.
- D9 (2026-11-15, analyst, immutability): that a completion was the minimal one is set on completion and not changed afterwards: a whole completion cannot be turned into a minimal one or the other way around; it is corrected by undoing and completing again. Editing or emptying the minimal version of the task does not touch its completions. Because completions are "only added: never modified" (§4.4).
- D10 (2026-11-15, analyst, the app does not suggest it): the minimal version is shown and offered the same way whenever it applies (D12), regardless of how overdue the task is, how many times the minimal version was done or any other data; there are no texts that propose it, counters of minimal versions or marks of "the minimal version again". No congratulations. Because the plan asks to avoid "that the app suggests it on its own" and rule 2 forbids counters; the count of minimal versions to validate is read by hand from the data ("Silence does not approve").
- D11 (2026-11-15, analyst, where the definition is not shown): the text of the minimal version is not shown in Anotaciones (§6.7) or in their copied text, and it does not change the name of the task (§4.1), which is still emoji and title. Of the completion, the Historial and the undo notice show only the word «Mínima» (D15, D16), never the text of the minimal version. Because it is the rule of the first step and the steps (D7 of `first-step`).
- D12 (2026-11-15, analyst, in which rows it is offered; reconciled with D14 and D18): the line «Mínima: …» and its «Hice la mínima» button are shown only in `pending` and `overdue` rows, decided with the status of each moment, never in `waiting` (postponed and completed ones included) or in paused ones; an `overdue` task with the checkbox disabled by its window shows it, with the button disabled (D7). A postponed task can still be completed whole with the checkbox (§5.9), not with the minimal version. Because it is the rule that the user already chose for the step line (D10 and D13 of `first-step`, D4 of `one-step-at-a-time`).
- D13 (2026-11-15, user, scope): P1 «Otra feature, después (Recomendada)» (translation: «Another feature, later (Recommended)»). The «cuenta como hecha cuando…» field of E4 is left out of this feature and is noted as a future feature of E4, with its own analysis.
- D14 (2026-11-15, user, how it is marked): P2 «Botón en la fila (Recomendada)» (translation: «Button in the row (Recommended)»). A button in the row, next to the text of the minimal version, completes the task as the minimal one; the checkbox still completes the whole task.
- D15 (2026-11-15, user, Historial): P3 «La palabra «Mínima» (Recomendada)» (translation: «The word «Mínima» (Recommended)»). The usual entry (current name and time) with the word «Mínima» after the time, in the same secondary text, without color or icon; the Borrar dialog names it the same way.
- D16 (2026-11-15, user, undo notice): P4 «Con la misma palabra del Historial (Recomendada)» (translation: «With the same word as the Historial (Recommended)»). «Completaste «🌱 Regar» · mínima», with «Vuelve …» below if it is recurring and **Deshacer** as always.
- D17 (2026-11-15, user, with steps): P5 «Dos líneas, la mínima en cualquier paso (Recomendada)» (translation: «Two lines, the minimal version on any step (Recommended)»). The row shows first the step line and below it the minimal version line; the minimal version can be done on any step, and doing it completes the task like the checkbox: it stores in `pasoAlCompletar` the step the task was on and returns to step 1; undoing it gives back that step (§4.1, **Steps**; §5.4).
- D18 (2026-11-15, user, row words): P6 ««Mínima: …» y botón «Hice la mínima» (Recomendada)» (translation: ««Mínima: …» and «Hice la mínima» button (Recommended)»). Line «Mínima: Solo el inodoro» and button «Hice la mínima».
- D19 (2026-11-15, analyst, how the line looks): the line «Mínima: » followed by the text goes on its own line below the title (below the step line, if there is one, D17), in full and on several lines if needed, without cutting, in the size and secondary text color of the step line, without emphasis or its own color. It is shown even if the task has no first step. «Hice la mínima» is a small text button without its own color, like **Hecho** and **Paso anterior**; tapping it does not open the panel or go through **Unsaved changes**, and it opens the undo notice (D16). Tapping the text of the line outside the button is tapping the row (it opens the panel). Because it is the rule of the step line (§6.1) and the user chose a separate line (D17).
- D20 (2026-11-15, analyst, changes for the spec-writer): textual rules of the spec that this feature changes and that must be rewritten, not only added beside:
  - §4.1 **Steps**, **Complete**: «Completing the task, by the checkbox or by «Hecho», returns `pasoActual` to step 1» now also names «Hice la mínima» (D17), and `pasoAlCompletar` is also stored in a completion of the minimal version of a task of two steps or more.
  - §4.1 **First step** and **Steps**, **No other effects** («they are not shown in the Historial, in the undo notice…»): still hold; the word «Mínima» of the Historial and of the notice does not show steps or the text of the minimal version (D11).
  - §4.4: the completion adds the data that says it was the minimal one (without the data, whole; there is no migration), set on completion (D9).
  - §5.4: the text of the notice «Completaste «…»» adds « · mínima» for a completion of the minimal version (D16); the rest of the notice does not change.
  - §5.5: «the checkbox that would complete is disabled» extends to «Hice la mínima» (D7).
  - §6.1: the row adds the line «Mínima: …» with its button (D12, D18, D19); the sentence «Tapping them does not open the panel, does not go through Unsaved changes and does not open an undo notice, except the «Hecho» of the last step» does not apply to «Hice la mínima», which does open the notice.
  - §6.2: the «Versión mínima» field in the **Tarea** section (D3) and its place in **Panel presentation** (order of the Tarea section: after the steps and before the note); it counts for **Unsaved changes** (D4).
  - §6.3: the entry and the dialog of **Borrar** add «Mínima» (D15); the rest stays the same («the completion does not store title or emoji»: it does not store the text of the minimal version either).
  - §7: the new field of the task in the list of independent fields of **Conflicts** (D5).

  - Edge case that cannot be written as Gherkin and goes to unit and property tests of the core: «Hice la mínima» on a task without a minimal version or that is neither `pending` nor `overdue` (the action is not offered, and the core does not complete).
