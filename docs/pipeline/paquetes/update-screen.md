# Package: update-screen

When the app opens or comes back from the background with nothing open (no panel, preview or dialog, D28) and there is a new version, an update screen shows the progress of the download (a bar with a percentage, the size, the current and the latest version) with a visible «Continuar sin actualizar» button that sends the download to the background; if the download (fonts and emoji set included) finishes on that screen, the app restarts in the new version. After «Continuar sin actualizar», or when the new version is found while something is open (D28), the download goes on in the background and a notice «Hay una versión nueva» with «Actualizar» appears when it is ready, in its own place above the undo notice (D29), until «Actualizar» is tapped or the app restarts (D30). A sixth and last item «Versión» of the **⋮** menu opens a dialog with the current version, the latest version, the status and the size of the download.

**Order**: the implementation chain starts after history-in-menu is merged into `v3` (its spec is already in `docs/spec.md`): both touch §6.1 **Menu and minimal mode** and the menu component.

## Specs

- **S1** (§2): «Update screen when there is a new version, and the version information (§6.8).»
- **S2** (§5.4): «The notice «Hay una versión nueva» (§6.8) is not part of this single slot: it has its own place above this notice and never replaces it nor is replaced by it.»
- **S3** (§5.4): «The update screen (§6.8) can appear on coming back from the background while this notice (or «Tareas reprogramadas») is open: that does not close it nor stop its 5 seconds, so after «Continuar sin actualizar» within those 5 seconds it is shown again. If the app restarts instead, the notice is closed: the completion stays and can be deleted from the **Historial**, like one left without a notice by another (above).»
- **S4** (§6): «**Offline and no external services**: the font and the complete emoji set (about 5.8 MB compressed) travel with the app, without being requested from an external service, and work offline, also for an emoji that was never seen on that device. Each device downloads them without asking or notifying, separately from the installation of the app: on the first start on a device, while the loading screen (§6.6) is open, the app waits for the download, and if the cap of that screen is reached the download continues in the background; the app is always installed, even if the font or the emoji set cannot be downloaded, and the fonts are downloaded with retries. If the emoji set (Noto) fails, the app is still available offline, with the device emoji. Whoever already has the app receives them with the next version, inside the single progress of the update screen (§6.8, §8), and the restart does not wait for them again.»
- **S5** (§6): «**Scope**: it applies to all the screens of the installed app (**Pendientes**, **Historial**, the panel and its notices, the sign-in screen, the loading screen, §6.6, the update screen and the «Versión» dialog, §6.8), without exceptions.»
- **S6** (§6): «**New version**: whoever already has the app installed receives the change without reinstalling, through the update screen or the «Hay una versión nueva» notice (§6.8), like any new version (§8); the system may take a few openings to apply it.»
- **S7** (§6.1): «**Menu and minimal mode**: the header of **Pendientes** has a small **⋮** button, with the accessible name «Menú», that opens a menu with six items, in this order: «Historial», **Modo mínimo**, "Completadas" (**Mostrar completadas**, below), "Pausadas" (**Mostrar pausadas**, below), **Reprogramar vencidas** (below) and «Versión». **Modo mínimo**, "Completadas" and "Pausadas" are on/off items: each one shows a check mark when on, and tapping it acts at that moment, without confirmation: it turns its value on or off (§5.8 for the mode) and closes the menu. «Historial» is a plain item (it has no check mark, it is not an on/off item): tapping it closes the menu and opens the **Historial** (§6, **Navigation**). It is always enabled, also with the mode on and with no completions. «Versión» is also a plain item, the sixth and last, below **Reprogramar vencidas**: tapping it closes the menu and opens the «Versión» dialog (§6.8); it is always enabled, also with the mode on. The menu has no other items. The three on/off items are always enabled, also with the mode on and with nothing to show. Nothing outside the menu shows the value of "Completadas" or "Pausadas" (there is no indicator in **Pendientes**), except the rows themselves. While the mode is on, above the list there is a line with the text «Modo mínimo» in secondary text, without color, icon or counter. It is only text (tapping it does nothing) and it is shown even if the list is empty (with the mode on and no essential task, the list is empty with that line). Turning the mode on or off does not show any other message (§5.8).»
- **S8** (§6.1): «**Reprogramar vencidas** (§5.11): the fifth item of the **⋮** menu, between "Pausadas" and «Versión». It is **disabled** (shown dimmed, tapping it does nothing and the menu stays open) whenever there is no overdue recurring task in view, including when the only overdue tasks are one-off ones or, with the minimal mode on, non-essential ones; the menu always looks the same. Enabled, tapping it closes the menu and opens a **preview**: a title «Reprogramar vencidas», a line «Vuelven como recién creadas, desde ahora.», the list of the tasks that will be rescheduled, and the buttons **Reprogramar** and **Cancelar**. Each row shows only the emoji and the title (§4.1), in the order of this section, with no «Tocaba …», no date, no checks and no count. The preview follows the data and the clock while it is open: a task that another device completed, deleted or paused, or that stops being an overdue recurring task, leaves it, and one that becomes one enters it. **Reprogramar** acts on all the tasks that are in the preview at that moment, without further confirmation, closes the preview and shows the notice of §5.4. If the preview is left with no task, **Reprogramar** is disabled and it can only be closed; **Cancelar** closes it and changes nothing.»
- **S9** (§6.1): «A **+** button creates a new task with the same panel. It sits at the bottom edge of the screen, without covering the last row. The last row is not covered either by the undo notice (§5.4) or by the «Hay una versión nueva» notice (§6.8), alone or both stacked: the list reserves at the bottom the real height of the notices shown.»
- **S10** (§6.2): «**Over the panel**: the emoji picker, the confirmation of **Borrar tarea** and the notices of **Unsaved changes** open over the panel, as always; on closing them it returns to the same tab. In full screen, the "Sin conexión" strip (§7) and the undo notice (§5.4, above the **Guardar** bar; with the bar hidden by the keyboard, above the keyboard) stay visible without covering the header, the tabs or **Guardar**. The notice can pass over the content during its 5 seconds. The «Hay una versión nueva» notice (§6.8) also stays visible over the panel, above the undo notice (and, with the bar hidden by the keyboard, above the keyboard), without covering the header, the tabs or **Guardar**; since it does not expire, the content of each tab reserves its height so that the end of the tab can be scrolled into view uncovered.»
- **S11** (§6.2): «**Reloading or closing the app** with unsaved changes shows the browser confirmation. It appears only if there are changes, with a notice open or without one, and never by **Back** with the panel open. Its text is the browser's and, where the system does not offer it, what was written is lost. On reload, the panel is not reopened. **Actualizar** of the «Hay una versión nueva» notice (§6.8) reloads the app, so with unsaved changes it shows this same confirmation, and if it is canceled the notice stays. Coming back from the background with the panel open (with or without changes) does not show the update screen (§6.8). A **Back** after a reload can return to the same screen without a visible effect.»
- **S12** (§6.3): «The last entry is not covered by the undo notice, the «Hay una versión nueva» notice (§6.8, alone or stacked above the undo notice), the "Sin conexión" strip (§7) or the bottom edge of the screen.»
- **S13** (§6.6): «**When it appears**: every time the app **starts** (open, reload, open with a new version) and on any destination screen, from the first thing the app draws. The loading screen does not appear when returning from the background if the app is still alive (the update screen can, §6.8), nor after tapping **Entrar con Google** (§6.5). The screen that the system draws when opening an installed PWA is left out (as in §6, Scope).»
- **S14** (§6.6): «**What is seen**: the app icon with a **slow, soft pulse**, without flicker, spin or progress indicator, and **without visible text**. When it finds a new version it becomes the update screen (§6.8), which does show progress and texts; the loading screen itself keeps this rule. The icon has the accessible name «Cargando». With the system's reduced-motion preference (`prefers-reduced-motion`) the icon is shown still; the rest does not change. It follows the light or dark theme of the system (§6).»
- **S15** (§6.6): «**It goes away by itself**: nothing is tapped on it and it does not announce anything technical (neither fonts, nor downloads, nor sync). The "Sin conexión" strip (§7) is seen only on entering the app. The update screen (§6.8) is another screen: it has a button, announces a download and shows the strip.»
- **S16** (§6.6): «**What it waits for with a session**: the response of Auth and the **first response** of tasks, of completions and of the state of the minimal mode (§7) (from the local cache or from the network), and also the **Atkinson Hyperlegible Next** font and **Noto Color Emoji**, even if they have to be downloaded, and, **only with a connection**, the answer to «is there a new version?» (§6.8). It goes away when all that is ready, with a **minimum of 0.5 seconds** even if everything is ready right away.»
- **S17** (§6.6): «**Without a session**: it does not wait for data, because there is none. It waits for the response of Auth, **only Atkinson** and, only with a connection, the answer about a new version (§6.8); Noto keeps downloading behind. It gives way to the sign-in screen (§6.5), which does not change, also offline. If Noto did not arrive on entering, the emoji are shown for a while with the device ones and change by themselves.»
- **S18** (§6.6): «**10-second cap**: it is a single one for the data, the fonts and the answer about a new version, and it counts from when the app starts; the wait for Auth does not count toward the cap. It does not apply to the update screen (§6.8): if the answer arrives after the cap, the app has already entered and the new version is treated like «Continuar sin actualizar». When it is reached, the app enters with what there is, as today, and the list is completed by itself, without a notice; what is missing of the font or of the set is shown with the fallback (§6). The download does not start again and each thing changes by itself when it arrives; if the download is aborted by a network failure, what §6 says applies (it is requested again when the connection recovers).»
- **S19** (§6.6): «**It does not wait for what is not going to arrive**: offline it waits for nothing that can only come over the network (not even the answer about a new version): it goes away when the local cache has responded and the already stored fonts are ready. A font that failed, or a set that the browser cannot draw, stops being waited for at that moment, even if the retries continue; whatever else is pending is still waited for until the cap. Losing the connection with the screen open counts the same. The 0.5 s minimum applies in all cases.»
- **S20** (§6.6): «**New version**: a new version that does not change the font or the set does not download them again, and opening it does not wait for them again. A new version that changes them downloads them on the update screen (§6.8), inside its single progress, and the restart does not wait for them again.»
- **S21** (§6.6): «**After a cap with Noto not downloaded**: the next openings with a session **do not wait for Noto** until it is stored, and it keeps downloading behind. Only a cap reached with Noto not downloaded in an opening that waited for it counts; an opening without a session does not wait for it, so it does not count. The device remembers it: it applies only on that device (it is not synced, it is not in Firestore, §7), it is not seen, and it is forgotten when Noto is stored. A new version that changes the set treats it as not stored and downloads it on the update screen (§6.8); that memory is forgotten when Noto is stored, whichever screen stores it.»
- **S22** (§6.8): «Version information and the screen that applies a new version. Versions are never synced: the data of this section is local to each device and is not written to Firestore (§7); nothing about it is remembered on the device either (there is no «skipped version»), so after «Continuar sin actualizar» the next opening or return from the background asks again.»
- **S23** (§6.8): «**A version** is shown as its number and its date: «Versión 412 · 24 de noviembre de 2026 · 11:20». The number goes up by itself with each published version and is never set by hand: the build computes it from the number of changes (commits) in the history that is built. The date is the date and time of the build (`$app/env` `version`), in local time, with the month in words and 24 h time (§6.3). The `package.json` version is not shown. The build writes `build/_app/version.json` with `version` (the build timestamp), `number` and `files` (each file of the version with its `size` in bytes: the precache, the fonts and the emoji set); that file is read from the network, without reloading, to learn the latest version.»
- **S24** (§6.8): «**Size of the download**: the sum of the `size` of the files of the latest version that the device does not have stored yet (so it includes the fonts and the set only when the new version changes them). It is shown in decimal megabytes with one decimal and a comma, «1,4 MB», and below 1 MB in kilobytes without decimals, «512 KB».»
- **S25** (§6.8): «**Progress**: a single bar and a single percentage for the whole download, fonts and set included, computed by bytes stored over the size of the download and shown as «45 %» (rounded down: «100 %» only when everything is stored). The files are downloaded one by one, so the progress moves evenly.»
- **S26** (§6.8): «**Status** (the same texts on the update screen and in the dialog): «Al día» when the latest version is the current one; «Descargando 45 %» when there is a new version and its download is not complete; «Lista: tocá Actualizar» when the new version is completely downloaded and not applied yet; «Sin conexión: no se pudo consultar» when the app could not ask (offline).»
- **S27** (§6.8): «**When it asks** («is there a new version?»): on opening with a connection (the loading screen waits for the answer, counted toward its 10 s cap, §6.6) and when coming back from the background (the app is shown at once as it was; the answer arrives afterwards). It asks with and without a session (the version does not depend on the session, so it also applies before the sign-in screen, §6.5). It does not ask, and so there is no update screen, offline (the app opens with the loading screen as today, or comes back as it was), nor the first time the app is opened on a device (there is no installed version: it already runs the latest and installs in the background, §8).»
- **S28** (§6.8): «**When the update screen appears**: when the answer says there is a new version and **nothing is open**. On opening the loading screen becomes the update screen; on coming back from the background the update screen appears over the app. **Something open** is exactly: the edit panel (with or without unsaved changes, and what opens over it: the emoji picker, the **Borrar tarea** confirmation and the notices of **Unsaved changes**, §6.2), the **Reprogramar vencidas** preview (§5.11), the «Versión» dialog and the dialogs of the **Historial** (the **Borrar** confirmation, §6.3). The open **⋮** menu and the notices (undo, «Tareas reprogramadas», «Hay una versión nueva») do not count: the update screen covers them. On opening nothing can be open (on reload the panel is not reopened, §6.2), so this only acts when coming back from the background. With something open the screen does not appear and the download goes on in the background (notice, below); closing what was open afterwards does not bring the screen: the next moment it can appear is the next opening or return from the background. If on opening the answer arrives after the 10 s cap of §6.6, or when coming back from the background the answer arrives with something open, it is treated like «Continuar sin actualizar». A window of the app already open on the computer is not reloaded when another window installs the version: it keeps its version until it is reloaded, opened again or comes back from the background, and then these rules apply (with the download already done and nothing open, the update screen restarts it at once).»
- **S29** (§6.8): «**What the update screen shows**, from top to bottom: the app icon (with the pulse of §6.6; still with `prefers-reduced-motion`), the status line («Descargando 45 %»), the bar with the percentage, the size of the download («1,4 MB»), the current version and the latest version (number and date, as above) and the button «Continuar sin actualizar». The progress bar keeps advancing with `prefers-reduced-motion`. It follows the theme of the system, the bundled font of the installed version with the same fallback (§6; the new fonts are not used until the restart) and the portrait orientation of the installed app (§6). On the phone (390 px wide) and on wide screens the button is always in view without scrolling and is not covered by the bottom edge of the screen or by the "Sin conexión" strip (§7), which the update screen does show.»
- **S30** (§6.8): «**How long it lasts**: the 10 s cap of §6.6 does not apply: the update screen stays until the download finishes or «Continuar sin actualizar» is tapped, however long that takes.»
- **S31** (§6.8): «**When the download finishes on the update screen** (fonts and set included) the app restarts by itself in the new version, without asking. The restart is a start like any other: the loading screen appears and waits for what §6.6 says, but the fonts and the set of the new version are already stored, so it does not wait for them again.»
- **S32** (§6.8): «**«Continuar sin actualizar»**: the text of the button is exactly «Continuar sin actualizar». It enters the app with the version it already has, and the download goes on in the background. On a start, §6.6 still decides when the app has enough to be shown: if the data or the fonts of that opening are not ready, the screen keeps waiting for them like the loading screen (same 0.5 s minimum and same 10 s cap counted from the start, so after a long wait it usually enters at once), without the button and without the progress. When coming back from the background it returns to the app as it was, without a loading screen.»
- **S33** (§6.8): «**If the download fails** on the update screen, the screen stays with the bar at the percentage it reached and the status «Descargando 45 %»; the "Sin conexión" strip (§7) is shown on it while there is no network; when the connection returns, the download resumes by itself from what was already stored. «Continuar sin actualizar» stays enabled.»
- **S34** (§6.8): «**The notice «Hay una versión nueva»**: after «Continuar sin actualizar», or when the new version was found with something open, the download goes on in the background and, **only when it is complete** (status «Lista: tocá Actualizar»), a notice appears with the text exactly «Hay una versión nueva» and a single button, «Actualizar». It never appears while downloading. It stays, also when changing screens, until «Actualizar» is tapped or the app restarts; there is no other way to close it. «Actualizar» reloads the app in the new version without another wait; with unsaved changes in the panel the browser confirmation of §6.2 applies, and if it is canceled the notice stays. It works offline: the new version is already fully stored, so the restart opens it like any offline opening.»
- **S35** (§6.8): «**Where the notice sits**: on every screen where the undo notice can be (**Pendientes**, the **Historial** and over the panel, §6.2) and on the sign-in screen; not on the loading screen or the update screen. It has the same horizontal place and width as the undo notice (beside the **+** button, which it does not cover). Alone, it sits at the bottom edge of the screen. When the undo notice or «Tareas reprogramadas» (§5.4) is also shown, that one keeps its place at the bottom edge and the version notice sits right above it, both fully visible, without overlapping; when that one expires the version notice goes back down to the bottom edge. §5.4 does not change: its single slot is only for the undo notice and «Tareas reprogramadas». The content reserves at the bottom the real height of the notices shown (one or the two stacked), so the last row of **Pendientes** and the last entry of the **Historial** can always be scrolled into view uncovered, whatever the length of the texts.»
- **S36** (§6.8): «**The notice and the connection strip** are independent: the strip stays at the top and the notices at the bottom, so both can be seen at once; going offline does not hide the notice.»
- **S37** (§6.8): «**The «Versión» dialog**: opened from the «Versión» item of the **⋮** menu (§6.1; the menu exists only in **Pendientes**, so it is not available on the sign-in screen). It shows «Actual: » and «Última: » with a version each (number and date), «Estado: » with the status (above) and, while there is a download pending or done, «Tamaño: » with its size. With «Lista: tocá Actualizar» it has an **Actualizar** button that does the same as the one of the notice; it always has **Cerrar**, and **Back** closes it without leaving **Pendientes** (§6.2, **Back**). It does not ask by itself whether there is a new version: it shows what the app learned at the last opening or return from the background and follows the download while it is open. With «Al día» the latest version is the current one and there is no size. When the app could not ask (offline) it shows the current version and «Sin conexión: no se pudo consultar», without the «Última: » line.»
- **S38** (§7): «**Connection notice**: while there is no network a small, discreet notice (a strip) is shown with the text "Sin conexión"; it disappears on reconnecting. It is also shown on the update screen (§6.8, not on the loading screen) and coexists with the «Hay una versión nueva» notice. There is no counter or indicator of pending changes.»
- **S39** (§7): «**Font and emoji**: the bundled font and emoji set (§6) are part of what the app stores to work offline; they are downloaded separately from the installation of the app and with retries (§8): on the first start of a device, while the loading screen is open, the download is waited for, and if the cap is reached it continues in the background (§6.6); a new version that changes them downloads them with the update (§6.8). From when the screen goes away until they are available, those of the system and the device apply (§6). If they cannot be downloaded, the app is still installed and available offline.»
- **S40** (§8): «**Frontend**: SvelteKit + TypeScript, built as a static site (`adapter-static`), with an installable PWA (manifest + service worker). Manifest: `name` "Tareas Hogar", `short_name` "Tareas"; icon and colors with the palette of the app; portrait orientation (§6). A new version of the service worker is applied through the update screen when the app is opened or comes back from the background (§6.8), or with **Actualizar** of the notice «Hay una versión nueva» after «Continuar sin actualizar». That includes the font and the emoji set (§6), which are downloaded inside the same progress. The installation of the app (what it stores to work offline) does not depend on the font or on the emoji set: if a font file fails to download, the app is installed anyway and the fonts are downloaded separately, with retries; the failure of Noto leaves the app available offline, with the device emoji (§6). The wait of the loading screen (§6.6) has a cap and never prevents installing or using the app; the update screen has no cap, but «Continuar sin actualizar» always lets the person use the app.»

## Decisions

- D1 (2026-11-24, analyst): when the download of the new version (fonts and emoji set included, D13) finishes while the update screen is open, the app restarts by itself in the new version, without asking; that restart is a start like any other, so the loading screen (§6.6) appears and waits for what it waits for today, but the fonts and the set of the new version are already stored, so it does not wait for them again. Because the request says so literally («en caso q la actualizacion se descargue por completo al app arranca en la ultima version») and D13 moves the font wait of that opening to the update screen. It never restarts with something open: in that case the update screen does not appear (D28).
- D2 (2026-11-24, analyst): «Continuar sin actualizar» enters the app with the version it already has. On a start, under the usual rules of §6.6: if the data or the fonts of that opening are not ready yet, the screen keeps waiting for them like the loading screen (same 0.5 s minimum, same 10 s cap counted from the start, so after a long wait on the update screen, D14, it usually enters at once), without the button and without the progress. When coming back from the background (D10), it returns to the app as it was, without a loading screen. The download continues in the background. Because the button only gives up waiting for the update; §6.6 still decides when the app has enough to be shown, and an app that was alive in the background already has it.
- D3 (2026-11-24, analyst): the first time the app is opened on a device (there is no installed version yet) there is no update screen: the app already runs the latest version and installs in the background as today (§8). Because there is no «current version» to update from and nothing to skip.
- D4 (2026-11-24, analyst): offline there is no update screen, neither on opening nor when coming back from the background: the app cannot learn whether there is a new version, so it opens with the loading screen as today (§6.6, «It does not wait for what is not going to arrive») or comes back as it was. Because §6.6 already says the start does not wait for what can only come over the network, and D11 waits for the answer only with a connection.
- D5 (2026-11-24, analyst): the update screen and the «Hay una versión nueva» notice also apply without a session (before the sign-in screen, §6.5): the version of the app does not depend on the session. The «Versión» item does not, because the **⋮** menu exists only in **Pendientes**. Because the service worker and the build are the same for both kinds of opening, and §6.6 already covers both.
- D6 (2026-11-24, analyst): the update screen follows the rest of the start screen: the system's light or dark theme (§6), the bundled font of the version already installed with the same fallback (§6) (the new fonts are part of the download, D13, and are not used until the restart), portrait in the installed app (§6, **Orientation**) and, on the phone (390 px wide) and on wide screens, the «Continuar sin actualizar» button is always in view without scrolling and is not covered by the bottom edge of the screen or the "Sin conexión" strip (§7), which the update screen does show (D24). The text of the button is exactly «Continuar sin actualizar». Because the request asks for a «visible» button with that text, and §6 and §6.6 already define the theme, font and orientation of the start screens.
- D7 (2026-11-24, analyst): with the system's reduced-motion preference, the icon of the update screen is shown still, as in §6.6; the progress bar keeps advancing (it is information, not decoration). Because §6.6 already applies that preference to the icon and says «the rest does not change».
- D8 (2026-11-24, analyst): other windows or tabs of the app that are already open (on the computer) are not reloaded at the moment a window installs the new version: each one keeps its version until it is reloaded, opened again or comes back from the background, and then the rules of D10 apply to it (with the download already done and nothing open, the update screen restarts it at once; with something open, the screen does not appear and the «Hay una versión nueva» notice is shown, D28, D31). Because reloading a window by itself while it is in view can lose what is being typed in its panel (§6.2, **Unsaved changes**), and D10 already defines the moments at which a window looks for a new version.
- D9 (2026-11-24, analyst): the version data is local to each device and is not written to Firestore or synced (§7): each device shows its own current version. Nothing new is remembered on the device either (no «skipped version» memory): after «Continuar sin actualizar», the next opening or return from the background looks again, by D10. So §7 **Local preferences** does not change. Because the version is a property of what each device has installed, not user data, and D10 already decides when the question is asked again.
- D10 (2026-11-24, user, Q1 when the update screen appears): «Al abrir y también al volver del segundo plano» (translation: «On opening and also when coming back from the background»). Option description: the phone app that stays alive for days also gets the update, but the screen can cut in while the person is in the middle of something (open panel, unsaved changes, §6.2).
- D11 (2026-11-24, user, Q2 whether the start waits for the answer): «Sí, espera la respuesta (solo con conexión) (Recomendada)» (translation: «Yes, it waits for the answer (only with a connection) (Recommended)»). Option description: the loading screen also waits for the answer to "is there a new version?"; if there is one it becomes the update screen; the wait counts toward the 10 s cap and offline nothing is waited for (§6.6); an online opening can last a little longer.

## Notes for the spec-writer and the gherkin-writer

**What exists today (verified in the code)**:

- The build version is the SvelteKit default: `version.name` is not configured in `vite.config.ts`, so `$app/env` `version` is the build timestamp in milliseconds (today `1795500533463`, published in `build/_app/version.json`). It is shown to a person as the **date and time of the build** (D20). `package.json` has `"version": "2.0.0"`, which is never bumped and is not used by the app; it is not the number of D20. There is no sequential number per deploy today: D20 produces it at build time from the history.
- `build/_app/version.json` is served by Hosting and is not in the service worker's precache (`immutable` and `assets` do not include it), so the page can read it from the network without reloading to learn the latest version (also when coming back from the background, D10). If it carries the number and the size (D20, D21), it has to be written by the build.
- The precache is about 1.4 MB in 33 files without the fonts; the fonts (`static/fuentes/`) add about 5.6 MB, are downloaded by the page (`src/lib/adapters/fonts.ts`) into their own cache, not by the service worker. D13 puts both in a single progress: the total size and the percentage add both, and the restart waits for both.
- The bottom reservation of history-in-menu (S3, S4, S7; in the pipeline worktree, `src/lib/ui/UndoNotice.svelte` publishes `--notice-height` and `src/lib/ui/styles.css` pads the content with `--notice-height` + `--notice-base`; the panel sets `--notice-base` above **Guardar** or the keyboard) measures one notice only. With D32 the reservation has to be the real height of the notices shown, the two stacked included, and the version notice has to sit on top of the undo notice when both are shown. The "Sin conexión" strip is at the top (`--strip-height`) and does not interact with the bottom notices.
- `cache.addAll` exposes no progress: a measurable progress by size (D12) needs the files to be downloaded one by one, with their sizes known in advance.
