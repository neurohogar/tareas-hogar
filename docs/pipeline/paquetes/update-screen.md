# Package: update-screen

When the app opens or comes back from the background and there is a new version, an update screen shows the progress of the download (a bar with a percentage, the size, the current and the latest version) with a visible «Continuar sin actualizar» button that sends the download to the background; if the download (fonts and emoji set included) finishes on that screen, the app restarts in the new version. After «Continuar sin actualizar», a notice «Hay una versión nueva» with «Actualizar» appears when the download is ready. A sixth and last item «Versión» of the **⋮** menu opens a dialog with the current version, the latest version, the status and the size of the download.

**Order**: the implementation chain starts after history-in-menu is merged into `v3` (its spec is already in `docs/spec.md`): both touch §6.1 **Menu and minimal mode** and the menu component.

## Decisions

- D1 (2026-11-24, analyst): when the download of the new version (fonts and emoji set included, D13) finishes while the update screen is open, the app restarts by itself in the new version, without asking; that restart is a start like any other, so the loading screen (§6.6) appears and waits for what it waits for today, but the fonts and the set of the new version are already stored, so it does not wait for them again. Because the request says so literally («en caso q la actualizacion se descargue por completo al app arranca en la ultima version») and D13 moves the font wait of that opening to the update screen. Whether the restart can happen with the panel open after coming back from the background (D10) is open question Q11.
- D2 (2026-11-24, analyst): «Continuar sin actualizar» enters the app with the version it already has. On a start, under the usual rules of §6.6: if the data or the fonts of that opening are not ready yet, the screen keeps waiting for them like the loading screen (same 0.5 s minimum, same 10 s cap counted from the start, so after a long wait on the update screen, D14, it usually enters at once), without the button and without the progress. When coming back from the background (D10), it returns to the app as it was, without a loading screen. The download continues in the background. Because the button only gives up waiting for the update; §6.6 still decides when the app has enough to be shown, and an app that was alive in the background already has it.
- D3 (2026-11-24, analyst): the first time the app is opened on a device (there is no installed version yet) there is no update screen: the app already runs the latest version and installs in the background as today (§8). Because there is no «current version» to update from and nothing to skip.
- D4 (2026-11-24, analyst): offline there is no update screen, neither on opening nor when coming back from the background: the app cannot learn whether there is a new version, so it opens with the loading screen as today (§6.6, «It does not wait for what is not going to arrive») or comes back as it was. Because §6.6 already says the start does not wait for what can only come over the network, and D11 waits for the answer only with a connection.
- D5 (2026-11-24, analyst): the update screen and the «Hay una versión nueva» notice also apply without a session (before the sign-in screen, §6.5): the version of the app does not depend on the session. The «Versión» item does not, because the **⋮** menu exists only in **Pendientes**. Because the service worker and the build are the same for both kinds of opening, and §6.6 already covers both.
- D6 (2026-11-24, analyst): the update screen follows the rest of the start screen: the system's light or dark theme (§6), the bundled font of the version already installed with the same fallback (§6) (the new fonts are part of the download, D13, and are not used until the restart), portrait in the installed app (§6, **Orientation**) and, on the phone (390 px wide) and on wide screens, the «Continuar sin actualizar» button is always in view without scrolling and is not covered by the bottom edge of the screen or the "Sin conexión" strip (§7), which the update screen does show (D24). The text of the button is exactly «Continuar sin actualizar». Because the request asks for a «visible» button with that text, and §6 and §6.6 already define the theme, font and orientation of the start screens.
- D7 (2026-11-24, analyst): with the system's reduced-motion preference, the icon of the update screen is shown still, as in §6.6; the progress bar keeps advancing (it is information, not decoration). Because §6.6 already applies that preference to the icon and says «the rest does not change».
- D8 (2026-11-24, analyst): other windows or tabs of the app that are already open (on the computer) are not reloaded at the moment a window installs the new version: each one keeps its version until it is reloaded, opened again or comes back from the background, and then the rules of D10 apply to it (with the download already done, the update screen restarts it at once; with the panel open, what Q11 decides). Because reloading a window by itself while it is in view can lose what is being typed in its panel (§6.2, **Unsaved changes**), and D10 already defines the moments at which a window looks for a new version.
- D9 (2026-11-24, analyst): the version data is local to each device and is not written to Firestore or synced (§7): each device shows its own current version. Nothing new is remembered on the device either (no «skipped version» memory): after «Continuar sin actualizar», the next opening or return from the background looks again, by D10. So §7 **Local preferences** does not change. Because the version is a property of what each device has installed, not user data, and D10 already decides when the question is asked again.
- D10 (2026-11-24, user, Q1 when the update screen appears): «Al abrir y también al volver del segundo plano» (translation: «On opening and also when coming back from the background»). Option description: the phone app that stays alive for days also gets the update, but the screen can cut in while the person is in the middle of something (open panel, unsaved changes, §6.2).
- D11 (2026-11-24, user, Q2 whether the start waits for the answer): «Sí, espera la respuesta (solo con conexión) (Recomendada)» (translation: «Yes, it waits for the answer (only with a connection) (Recommended)»). Option description: the loading screen also waits for the answer to "is there a new version?"; if there is one it becomes the update screen; the wait counts toward the 10 s cap and offline nothing is waited for (§6.6); an online opening can last a little longer.
- D12 (2026-11-24, user, Q3 what progress shows): «Barra con porcentaje por tamaño (Recomendada)» (translation: «Bar with a percentage by size (Recommended)»). Option description: for example «45 %», computed by what has been downloaded; moves evenly even if one file is much bigger than the others.
- D13 (2026-11-24, user, Q4 whether the fonts count in the progress): «Sí, un solo progreso para todo» (translation: «Yes, a single progress for everything»). Option description: the app restarts only when the fonts are also stored; a single wait, longer when the set changes; the font wait of §6.6 for that opening moves to the update screen.
- D14 (2026-11-24, user, Q5 how long the update screen waits): «Hasta que termine o toques el botón (Recomendada)» (translation: «Until it finishes or you tap the button (Recommended)»). Option description: the 10 s cap of §6.6 does not apply to the update; the person decides; if they put the phone down the screen can stay there for a long time.
- D15 (2026-11-24, user, Q6 what happens if the download fails): «Se queda en la pantalla y retoma sola al volver la conexión» (translation: «It stays on the screen and resumes by itself when the connection returns»). Option description: the button still lets the person leave; no extra step, but without a connection the person waits until they tap the button.
- D16 (2026-11-24, user, Q7 when the new version is applied after «Continuar sin actualizar»): «Un aviso discreto «Hay una versión nueva» con botón Actualizar» (translation: «A discreet notice «Hay una versión nueva» with an «Actualizar» button»). Option description: the person chooses the moment: the app reloads when they tap; with unsaved changes in the panel the browser confirmation of §6.2 applies; it adds a notice and contradicts the "without notice" of §8. The question was asked with two options only: the third (reload by itself when coming back from the background) was dropped because D10 already covers that moment.
- D17 (2026-11-24, user, Q8 where the version information is shown): «En la pantalla de actualización y en un ítem «Versión» del menú ⋮ (Recomendada)» (translation: «On the update screen and in a «Versión» item of the ⋮ menu (Recommended)»). Option description: the item opens a dialog with the current version, the latest version and the update status; it can be checked at any time; the menu goes to six items and touches §6.1, so the implementation chain starts after history-in-menu is merged into v3 (its spec is already in docs/spec.md: the menu has five items with «Historial» first, so «Versión» is the sixth and last).
- D18 (2026-11-24, user, Q9 how a version is shown): «Ambos, número y fecha» (translation: «Both, number and date»). Option description: the most complete, with the same cost as the number: each deploy has to bump the number in the code; if someone forgets, two versions look the same. (`package.json` is "2.0.0" and is never bumped today: decide how the number is produced, as an analyst decision with its reason.)
- D19 (2026-11-24, user, Q10 what «el etc.» is): «El estado y el tamaño de la descarga» (translation: «The status and the size of the download»). Option description: for example «1,4 MB», useful on mobile data; one more technical detail on the screen. The options were adapted to the earlier answers: the status texts are «Al día», «Descargando 45 %», «Lista: tocá Actualizar» (from D16) and «Sin conexión: no se pudo consultar».
- D20 (2026-11-24, analyst): the number of a version goes up by itself with each published version and is never set by hand: it is produced when the app is built from the number of changes (commits) in the history that is built, and shown as «Versión 412». The date is the date and time of the build (today's `$app/env` `version` timestamp), in local time, with the month in words and 24 h time as in §6.3: «24 de noviembre de 2026 · 11:20». `package.json` «2.0.0» is not shown. Because D18 asks for both, the option warned that a hand-bumped number is forgotten, and a number counted from the history can only go up along the integration branch; if two builds of the same history ever share a number, the date tells them apart.
- D21 (2026-11-24, analyst): the update screen shows, from top to bottom: the app icon (with the pulse of §6.6 and D7), the status line (the same texts as the dialog, D19: «Descargando 45 %»), the bar with the percentage (D12), the size of the whole download («1,4 MB», D19; it includes the fonts and the set when the new version changes them, D13), the current version and the latest version (number and date, D20), and the «Continuar sin actualizar» button. Because D17 and D19 put the version information and the size also on the update screen, and the status texts already exist for the dialog.
- D22 (2026-11-24, analyst): with a connection, on opening, the loading screen waits for the answer to «is there a new version?» (D11); if it does not arrive before the 10 s cap, the app enters as today, and an answer that arrives later with a new version is treated like «Continuar sin actualizar»: the download goes to the background and the notice appears when it is ready (D16). When coming back from the background, the app is shown at once as it was (there is no loading screen, §6.6) and the update screen appears only if the answer says there is a new version. Because the cap of §6.6 still bounds the start (D11 counts the wait toward it), and when coming back from the background nothing has to be waited for to show the app.
- D23 (2026-11-24, analyst): the «Hay una versión nueva» notice (D16) appears only when the download is complete (status «Lista: tocá Actualizar»), never while it is downloading: «Actualizar» restarts in the new version without another wait. It is shown on **Pendientes**, on the **Historial** and over the panel in the same place as the undo notice (§5.4, §6.2 **Over the panel**), and stays visible when changing screens. Tapping «Actualizar» reloads the app; with unsaved changes in the panel the browser confirmation of §6.2 applies (D16). Its lifetime and whether it shares the single notice slot of §5.4 are open questions Q12 and Q13. Because D16 says «Actualizar» applies the new version, which needs it downloaded, and the status «Lista: tocá Actualizar» names that moment.
- D24 (2026-11-24, analyst): when the download fails on the update screen (D15), the screen stays with the bar at the percentage it reached and the status line «Descargando N %», and the "Sin conexión" strip (§7) is shown on it while there is no network; when the connection returns, the download resumes from what was already stored, by itself. «Continuar sin actualizar» stays enabled. Because D15 says it stays and resumes by itself, and without the strip the person could not tell why the bar stopped; the loading screen keeps its rule of not showing the strip (§6.6).
- D25 (2026-11-24, analyst): the «Versión» item of the **⋮** menu (D17) is a plain item (no check mark, like «Historial»), the sixth and last, below **Reprogramar vencidas**; its text is exactly «Versión». It is always enabled, also with the minimal mode on. Tapping it closes the menu and opens the dialog. Because D17 says it is the last item, and «Historial» already sets the rule for plain items.
- D26 (2026-11-24, analyst): the «Versión» dialog shows the current version and the latest version (number and date, D20), the status (D19: «Al día», «Descargando 45 %», «Lista: tocá Actualizar», «Sin conexión: no se pudo consultar») and, while there is a download pending or done, its size. With «Lista: tocá Actualizar» it has an «Actualizar» button that does the same as that of the notice (D23); it always has «Cerrar», and **Back** closes it without leaving **Pendientes** (like the other things that open over the screen, §6.2 **Back**). It does not ask by itself whether there is a new version: it shows what the app learned at the last opening or return from the background (D10) and follows the download while it is open. When the app could not ask (offline, D4) it shows the current version and «Sin conexión: no se pudo consultar», without a latest version line. With «Al día» the latest version is the current one. Because the status text «Lista: tocá Actualizar» needs an «Actualizar» within reach even if the notice is not in view, D10 already fixes the moments of asking, and showing a latest version the app does not know would mislead.
- D27 (2026-11-24, analyst): if the update screen appears (on coming back from the background) while the undo notice of §5.4 is open, its 5 seconds keep running; «Continuar sin actualizar» within those 5 seconds shows it again, and a restart closes it: the completion stays and can be deleted from the **Historial**, as with a notice replaced by another (§5.4). Because §5.4 already accepts a completion left without a notice and keeps the 5 seconds when the notice is not in view.

## Open questions for the user

- **Q11** (D10: the app comes back from the background with a new version while the edit panel is open, with or without unsaved changes; the same for the **Reprogramar vencidas** preview, the «Versión» dialog and the dialogs of the **Historial**):
  1. *(Recommended)* With something open, the update screen does not appear: the download goes to the background as after «Continuar sin actualizar» and, when it is ready, the «Hay una versión nueva» notice appears. Consequence: nothing written is lost and nothing cuts in; the update waits for «Actualizar» or the next opening or return from the background with nothing open.
  2. The update screen covers what is open and «Continuar sin actualizar» returns to it as it was; if the download finishes and there are unsaved changes, it does not restart by itself: it stays at «Lista: tocá Actualizar» until the person taps «Continuar sin actualizar». Consequence: the update always shows, but the screen interrupts the person in the middle of writing and adds a case where it does not restart by itself.
  3. The update screen appears only if the panel has no unsaved changes (an open panel without changes, the preview or a dialog are closed by the restart); with unsaved changes, option 1. Consequence: more updates happen at once, but a panel opened just to look closes by itself.
- **Q12** (D16: the «Hay una versión nueva» notice and the undo notice of §5.4, which has a single slot shared with «Tareas reprogramadas»):
  1. *(Recommended)* It shares the slot, with lower priority: a completion or a rescheduling covers it for their 5 seconds, and when they expire it is seen again. Consequence: there is never more than one notice at the bottom, and «Deshacer» always wins; «Actualizar» is out of reach for 5 seconds (it stays in the «Versión» dialog).
  2. It has its own place, above the undo notice: both can be seen at once. Consequence: «Actualizar» is always within reach, but there can be two notices stacked at the bottom, covering more of the list.
  3. It shares the slot like the other two: whichever comes last replaces the other for good. Consequence: a completion makes it disappear until the next opening; «Actualizar» remains only in the «Versión» dialog.
- **Q13** (D16: how long the «Hay una versión nueva» notice stays):
  1. *(Recommended)* Until «Actualizar» is tapped or the app restarts, with no other way to close it. Consequence: no extra button; it occupies the bottom of the screen until the next opening, which applies the version anyway (D10).
  2. It has a second button «Ahora no» that hides it until the next opening or return from the background. Consequence: the person can clear the screen; one more button, and «Actualizar» stays in the «Versión» dialog.
  3. It lasts 5 seconds, like the undo notice, and does not come back until the next opening. Consequence: the least intrusive; easy to miss, and then the update is only in the «Versión» dialog or the next opening.

## Notes for the spec-writer and the gherkin-writer

**What exists today (verified in the code)**:

- The build version is the SvelteKit default: `version.name` is not configured in `vite.config.ts`, so `$app/env` `version` is the build timestamp in milliseconds (today `1795500533463`, published in `build/_app/version.json`). It is shown to a person as the **date and time of the build** (D20). `package.json` has `"version": "2.0.0"`, which is never bumped and is not used by the app; it is not the number of D20. There is no sequential number per deploy today: D20 produces it at build time from the history.
- `build/_app/version.json` is served by Hosting and is not in the service worker's precache (`immutable` and `assets` do not include it), so the page can read it from the network without reloading to learn the latest version (also when coming back from the background, D10). If it carries the number and the size (D20, D21), it has to be written by the build.
- The precache is about 1.4 MB in 33 files without the fonts; the fonts (`static/fuentes/`) add about 5.6 MB, are downloaded by the page (`src/lib/adapters/fonts.ts`) into their own cache, not by the service worker. D13 puts both in a single progress: the total size and the percentage add both, and the restart waits for both.
- `cache.addAll` exposes no progress: a measurable progress by size (D12) needs the files to be downloaded one by one, with their sizes known in advance.

**Rules this feature rewrites** (the spec-writer rewrites each one; quoted from `docs/spec.md` as it is today, with history-in-menu already in it):

- §2, **Includes**: «Loading screen when the app starts (§6.6).»: add the update screen and the version information.
- §6.6, **When it appears**: «It does not appear when returning from the background if the app is still alive»: still true for the loading screen, but the update screen does appear when coming back from the background (D10, D22). It probably belongs in a new section for the update screen (the numbering of the others is not shifted).
- §6.6, **What is seen**: «without flicker, spin or progress indicator, and **without visible text**»: the update screen has a bar, a percentage, texts and a button (D12, D21). The loading screen itself keeps this rule.
- §6.6, **It goes away by itself**: «nothing is tapped on it and it does not announce anything technical (neither fonts, nor downloads, nor sync). The "Sin conexión" strip (§7) is seen only on entering the app.»: the update screen has a button, announces a download, and shows the strip (D24).
- §6.6, **What it waits for with a session** / **Without a session** / **10-second cap**: the loading screen also waits for the answer about a new version, only with a connection, counted toward the cap (D11, D22); the cap does not apply to the update screen (D14).
- §6.6, **New version**: «a new version that does not change the font or the set does not download them again, and opening it does not wait for them again»: a new version that changes them downloads them on the update screen, inside the single progress (D13), and the restart does not wait for them again (D1).
- §6.6, **After a cap with Noto not downloaded**: «A new version that changes the set treats it as not stored and waits for it once again»: now on the update screen (D13); check whether the memory is forgotten when the update screen stores the set.
- §6, **Bundled font and emoji**, **Offline and no external services**: «Whoever already has the app receives them with the next version, without asking or notifying (§8)», and «while the loading screen (§6.6) is open, the app waits for the download»: they arrive with the update screen (D13).
- §6, **Orientation**, **Scope** («all the screens of the installed app … and the loading screen, §6.6, without exceptions»): add the update screen and the «Versión» dialog. **New version**: «receives the change by itself, without reinstalling, asking or notifying, like any new version (§8)»: now through the update screen.
- §6.1, **Menu and minimal mode**: «a menu with five items, in this order: «Historial», **Modo mínimo**, "Completadas" …, "Pausadas" … and **Reprogramar vencidas**» and «The menu has no other items»: six items, «Versión» last (D17, D25).
- §6.1, **Reprogramar vencidas**: «the last item of the **⋮** menu, below "Pausadas"»: it becomes the fifth item, between "Pausadas" and «Versión». history-in-menu (its D6 and its §6.1 check) kept it last; this feature is what changes that.
- §5.4: «There is only one notice at a time» and the single slot shared with «Tareas reprogramadas»: depends on Q12; D27 adds what happens with the undo notice when the update screen appears.
- §6.2, **Over the panel** (which notices stay visible over the panel in full screen) and **Reloading or closing the app** (the browser confirmation): the «Hay una versión nueva» notice over the panel and «Actualizar» with unsaved changes (D16, D23); coming back from the background with the panel open depends on Q11.
- §6.3 last bullet («The last entry is not covered by the undo notice, the "Sin conexión" strip (§7) or the bottom edge of the screen») and §5.4 («without covering the last row or entry»): also for the «Hay una versión nueva» notice.
- §8: «A new version of the service worker is applied by itself the next time the app is opened, without asking or notifying. That includes the font and the emoji set (§6).»: it is applied through the update screen, on opening or on coming back from the background, or with «Actualizar» (D1, D10, D16). «The wait of the loading screen (§6.6) has a cap and never prevents installing or using the app»: the update screen has no cap (D14) but «Continuar sin actualizar» always lets the person use the app.
- §7, **Local preferences**: does not change (D9). §7 **Connection notice**: the strip is also shown on the update screen (D24).
