# Package: bundled-font

The app is shown with its own font and emoji, bundled with it, instead of the system ones, which change between machines.

## Specs

- **S1** (§6): «the app looks the same on all machines. All the text uses the **Atkinson Hyperlegible Next** font and every emoji is drawn with **Noto Color Emoji**; both travel with the app (§2, §7) and there is no option to change them.»
- **S2** (§6): «both apply to all text and every emoji on all screens (Pendientes, Historial, Etiquetas, the panel and its notices, the emoji picker with its Recientes, the undo notice and the sign-in screen), also in fields and buttons, and in both themes.»
- **S3** (§6): «Only the elements drawn by the system that the app does not control are left out (the phone keyboard, the native calendars and lists of a field).»
- **S4** (§6): «sizes, weights and visual hierarchy do not change, and times (`HH:MM`) keep fixed-width digits. **Only exception**: the **Título** field of the panel (§6.2) becomes **20px (1.25rem)**, larger than the **Nota**, which stays at 16px.»
- **S5** (§6): «the font and the complete emoji set (about 5.8 MB compressed) travel with the app, without being requested from an external service, and work offline, also for an emoji that was never seen on that device. Each device downloads them without asking or notifying, separately from the installation of the app: while the loading screen (§6.6) is open, the app waits for the download, and if the cap of that screen is reached the download continues in the background; the app is always installed, even if the font or the emoji set cannot be downloaded, and the fonts are downloaded with retries. If the emoji set (Noto) fails, the app is still available offline, with the device emoji. Whoever already has the app receives them with the next version, without asking or notifying (§8).»
- **S6** (§6): «from the moment the loading screen (§6.6) goes away, if the font or the emoji set have not been downloaded yet, or cannot be loaded, or the browser cannot draw the set, the text is shown with the system font and the emoji with the device one, without a notice, and they change by themselves when they are available. While the loading screen is open no fallback is shown: it waits for what is missing (§6.6). The text is never invisible and an emoji is never shown blank.»
- **S7** (§6): «| Text character that Atkinson does not have (another alphabet in a title, for example) | the system font |»
- **S8** (§6): «| Character with a text and an emoji version, without an emoji mark, that Atkinson does not have (`❤`, `☀`, `☎`, `✈`) | Noto Color Emoji |»
- **S9** (§6): «| Emoji that Noto does not have (from a newer Unicode version, arrived from another device) | the device emoji |»
- **S10** (§6): «bundling does not change which emoji are valid (§4.1) or which ones the picker offers (§6.2); an emoji that the set does not have is stored and shown all the same. Today Noto draws as a single glyph each of the emoji that the picker offers (including the single-skin-tone variants), so the picker does not lose any.»
- **S11** (§8): «That includes the font and the emoji set (§6). The installation of the app (what it stores to work offline) does not depend on the font or on the emoji set: if a font file fails to download, the app is installed anyway and the fonts are downloaded separately, with retries; the failure of Noto leaves the app available offline, with the device emoji (§6). The wait of the loading screen (§6.6) has a cap and never prevents installing or using the app.»
- **S12** (§6): «If the download of the emoji set is aborted by a network failure, the app requests it again when the connection recovers, without reloading, and the emoji changes by itself when it arrives.»
- **S13** (§6): «the app is always installed, even if the font or the emoji set cannot be downloaded, and the fonts are downloaded with retries. If the emoji set (Noto) fails, the app is still available offline, with the device emoji.»
- **S14** (§6.2): «The **Título** field is shown at 20px (1.25rem), larger than the **Nota** (16px; §6, No design changes).»
- **S15** (§7): «the bundled font and emoji set (§6) are part of what the app stores to work offline; they are downloaded separately from the installation of the app and with retries (§8): while the loading screen is open the download is waited for, and if the cap is reached it continues in the background (§6.6). From when the screen goes away until they are available, those of the system and the device apply (§6). If they cannot be downloaded, the app is still installed and available offline.»
- **S16** (§6.2): «The picker offers **1914 base emoji** with their **single-skin-tone variants**, grouped by category (with navigation between categories), and a **search in Spanish** (for example "planta", "escoba", "perro"). Choosing an emoji assigns it to the task and closes the picker. It does not offer the 9 emoji of the components group (the 5 skin tones and the 4 hair types alone) or the two-skin-tone variants. What arrives some other way is governed by §4.1: a lone skin tone is invalid and is rejected; a lone hair type (🦰, 🦱, 🦳, 🦲) and a two-tone variant (🧑🏻‍🤝‍🧑🏿) are a valid emoji, are stored and are shown all the same.»
- **S17** (§6.6): «On start, the app shows a **loading screen** instead of the blank page and the empty content of today.»
- **S18** (§6.6): «**When it appears**: every time the app **starts** (open, reload, open with a new version) and on any destination screen, from the first thing the app draws. It does not appear when returning from the background if the app is still alive, nor after tapping **Entrar con Google** (§6.5). The screen that the system draws when opening an installed PWA is left out (as in §6, Scope).»
- **S19** (§6.6): «**What is seen**: the app icon with a **slow, soft pulse**, without flicker, spin or progress indicator, and **without visible text**. The icon has the accessible name «Cargando». With the system's reduced-motion preference (`prefers-reduced-motion`) the icon is shown still; the rest does not change. It follows the light or dark theme of the system (§6).»
- **S20** (§6.6): «**It goes away by itself**: nothing is tapped on it and it does not announce anything technical (neither fonts, nor downloads, nor sync). The "Sin conexión" strip (§7) is seen only on entering the app.»
- **S21** (§6.6): «**What it waits for with a session**: the response of Auth and the **first response** of tasks, completions and labels (from the local cache or from the network), and also the **Atkinson Hyperlegible Next** font and **Noto Color Emoji**, even if they have to be downloaded. It goes away when all that is ready, with a **minimum of 0.5 seconds** even if everything is ready right away.»
- **S22** (§6.6): «**Without a session**: it does not wait for data, because there is none. It waits for the response of Auth and **only Atkinson**; Noto keeps downloading behind. It gives way to the sign-in screen (§6.5), which does not change, also offline. If Noto did not arrive on entering, the emoji are shown for a while with the device ones and change by themselves.»
- **S23** (§6.6): «**10-second cap**: it is a single one for the data and the fonts and it counts from when the app starts; the wait for Auth does not count toward the cap. When it is reached, the app enters with what there is, as today, and the list is completed by itself, without a notice; what is missing of the font or of the set is shown with the fallback (§6). The download does not start again and each thing changes by itself when it arrives; if the download is aborted by a network failure, what §6 says applies (it is requested again when the connection recovers).»
- **S24** (§6.6): «**It does not wait for what is not going to arrive**: offline it waits for nothing that can only come over the network: it goes away when the local cache has responded and the already stored fonts are ready. A font that failed, or a set that the browser cannot draw, stops being waited for at that moment, even if the retries continue; whatever else is pending is still waited for until the cap. Losing the connection with the screen open counts the same. The 0.5 s minimum applies in all cases.»
- **S25** (§6.6): «**New version**: a new version that does not change the font or the set does not download them again, and opening it does not wait for them again.»
- **S26** (§6.6): «**After a cap with Noto not downloaded**: the next openings with a session **do not wait for Noto** until it is stored, and it keeps downloading behind. Only a cap reached with Noto not downloaded in an opening that waited for it counts; an opening without a session does not wait for it, so it does not count. The device remembers it: it applies only on that device (it is not synced, it is not in Firestore, §7), it is not seen, and it is forgotten when Noto is stored. A new version that changes the set treats it as not stored and waits for it once again.»
- **S27** (§6.6): «Examples (with a session): everything ready at 0.2 s: it goes away at 0.5 s. The data arrives at 3 s and Noto at 6 s: it goes away at 6 s. Noto did not arrive by 10 s: it enters at 10 s with the device emoji and the next openings do not wait for Noto until it is stored.»
- **S28** (§2): «Loading screen when the app starts (§6.6).»
- **S29** (§7): «the recent emojis of the picker (§6.2) and the memory of a loading-screen cap with Noto not downloaded (§6.6) live only on the device (local browser storage); they are not written to Firestore or synced.»

- D1 (2026-11-04, user): «Empaquetar una fuente» (translation: «Bundle a font»), in answer to «La app usa hoy la fuente `system-ui`, que cambia entre máquinas. ¿El harness de UI/UX trabaja con una fuente empaquetada?» (translation: «The app uses the `system-ui` font today, which changes between machines. - D3 (2026-11-04, analyst): the font travels with the app and works offline, without being requested from an external service. Why: it is the same rule as the icons and the emoji catalog (§6.2, §7).
- D4 (2026-11-04, analyst): the text is never invisible: while the font is not available, or if it cannot be loaded, it is shown with the system font, without a notice, and changes by itself when it is available. Why: the app can always be used (§7), and technical things are applied without notifying (§8).
- D5 (2026-11-04, analyst): the font covers Spanish; a text character that it does not have (for example, another alphabet in a title) is shown with the system font. Why: the title is free text (§4.1) and must never be lost. Emoji follow the rules of D10 to D13. Updated after D9.
- D6 (2026-11-04, analyst): sizes, weights and visual hierarchy do not change, and times keep fixed-width digits. The presentation rules of the spec still hold with the new font. Why: the request changes the font, not the design; the rest is the harness's job.
- D7 (2026-11-04, analyst): whoever already has the app receives the font with the next version, without asking or notifying. Why: it is the rule of §8 for every new version.

- D14 (2026-11-04, analyst): a character that exists as text and as emoji, without an emoji mark (digits, `#`, `©`, `™`), is shown with the text font. Why: in a title they are text; D6 requires times to keep their fixed-width digits.
